# 21. Merge Two Sorted Lists

[Условие на LeetCode](https://leetcode.com/problems/merge-two-sorted-lists/) · **Easy** · Linked List

Даны два отсортированных односвязных списка. Нужно слить их в один отсортированный список,
переставляя существующие узлы, а не создавая новые.

## Ключевая мысль

Это шаг слияния из merge sort: смотрим на головы обоих списков, меньшую подвешиваем к хвосту
результата и сдвигаем её указатель. Когда один список кончился, остаток второго уже отсортирован
и подвешивается одной операцией.

**Фиктивный узел** (`dummy`) перед началом результата убирает частный случай «какой узел станет
головой» и «результат ещё пуст»: хвост всегда существует, ответ лежит в `dummy.next`.

## Почему именно так

- **Итеративно с dummy (выбран).** O(1) доп. памяти: узлы только перецепляются.
  Без dummy пришлось бы до цикла отдельно выбирать голову и проверять пустые списки.
- **Рекурсия** (`l1.next = merge(l1.next, l2)`) короче и красивая, но тратит O(n + m) стека.
  В Python лимит рекурсии около 1000, так что на длинных списках она падает. Здесь списки до 50 узлов,
  но на собеседовании лучше показать итеративный вариант и упомянуть рекурсивный.
- **Собрать значения в массив, `sorted()`, построить новый список**: O((n+m)·log(n+m)),
  создаёт новые узлы, хотя условие просит переиспользовать старые, и не использует то,
  что входы уже отсортированы.
- `<=` вместо `<` сохраняет устойчивость: при равных значениях первым идёт узел из `list1`.

## Сложность

- Время: **O(n + m)**, каждый узел просматривается один раз.
- Память: **O(1)** дополнительной памяти.

## Код

```python
class Solution:
    def mergeTwoLists(self, list1, list2):
        dummy = tail = ListNode()
        while list1 and list2:
            if list1.val <= list2.val:
                tail.next, list1 = list1, list1.next
            else:
                tail.next, list2 = list2, list2.next
            tail = tail.next
        tail.next = list1 or list2
        return dummy.next
```
