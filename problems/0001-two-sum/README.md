# 1. Two Sum

[Условие на LeetCode](https://leetcode.com/problems/two-sum/) · **Easy** · Hash Table

Дан массив чисел и цель `target`. Нужно вернуть **индексы** двух разных элементов,
которые в сумме дают `target`. Гарантируется ровно одно такое решение.
Порядок индексов в ответе не важен.

## Ключевая мысль

Для каждого числа `num` напарник известен заранее: это `target - num`.
Если запоминать уже просмотренные числа в словаре `значение -> индекс`,
проверка «напарник уже был» стоит O(1). Один проход слева направо находит пару,
как только встречается второй её элемент.

Число кладётся в словарь **после** проверки. Иначе на `[3, 3]` и `target = 6`
элемент нашёл бы сам себя.

## Почему именно так

- **Словарь, один проход (выбран).** O(n) по времени, O(n) по памяти.
  Индексы сохраняются, ранний выход на первой найденной паре.
- **Два вложенных цикла.** Перебирают все пары, O(n²). При n до 10⁴ это ещё проходит,
  но квадрат здесь ничем не оправдан: напарник ищется точно, а не «среди всех».
- **Сортировка и два указателя.** O(n log n) и O(1) доп. памяти по значениям,
  но сортировка теряет исходные индексы. Чтобы их вернуть, нужно тащить пары
  `(значение, индекс)` — код длиннее, а выигрыша по времени нет.
- **Два прохода** (сначала заполнить словарь, потом искать) тоже O(n), но без раннего
  выхода и с отдельной вознёй, чтобы не взять один индекс дважды. Один проход короче.

## Сложность

- Время: **O(n)**, один проход.
- Память: **O(n)** под словарь.

## Код

```python
class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        seen = {}
        for i, num in enumerate(nums):
            need = target - num
            if need in seen:
                return [seen[need], i]
            seen[num] = i
        return []
```
